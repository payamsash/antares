Operator Working Guide

Step-by-step instructions for running ANTARES neurofeedback sessions. This document is intended for the operator (researcher / clinician) — the person sitting at the control station while the participant is in the EEG chair.

Overview

ANTARES is a multi-session adaptive EEG neurofeedback protocol for tinnitus. The operator uses a single GUI (antares_app.py) to control all stages. A separate participant screen (antares_gui.py) runs full-screen on the second monitor facing the participant.

One rule to remember: always enter the correct visit number before clicking Start Full Protocol. The visit number determines baseline duration, analysis depth, and whether the NF target can still be changed.

First-Time Setup

  1. Install dependencies Run pip install -r requirements.txt from the project root. The rspv visualisation engine has its own venv at rspv/venv/ — activate and install rspv/requirements.txt separately if rspv is used.
  2. Edit config_master.yml Set the four path keys at minimum: 
    subjects_dir:    /data/subjects
audiometry_dir:  /data/audiometry
models_dir:      /data/models
site:            zuerich          # or basel
    The GUI reads this file on startup and pre-fills all fields. You rarely need to change anything in the GUI itself once the config is correct.
  3. Verify the LSL stream Turn on the EEG amplifier and confirm the LSL stream is broadcasting before opening ANTARES. If hardware is unavailable, enable Mock LSL in the Subject section and point it to a pre-recorded .xdf or .fif file.
  4. Place audiometry files Each subject's audiometry .mat files must be in <audiometry_dir>/<SUBJECT_ID>/. File names must start with <id> L or <id> R (case-insensitive). If a subject has no audiometry, PTA will be recorded as NaN and the session continues normally.
  5. Launch ANTARES 
    cd /path/to/antares
python antares_app.py
    The operator GUI opens. The participant screen is not launched automatically at startup — you launch it via the Participant Screen button when you are ready.

Before Every Session

  1. Seat the participant, fit the EEG cap, check impedances. Aim for <10 kΩ on all channels before proceeding.
  2. Open ANTARES and verify the sidebar fields. In particular: Subject ID, Age, Sex, and — most importantly — the correct Visit Number.
  3. Click Participant Screen to open the full-screen participant display on the second monitor. It will show a dark waiting screen with animated dots. The participant should now be looking at their screen.
  4. Explain the session to the participant before starting. For visit 1, explain the resting baseline ("relax with eyes open, look at the fixation cross, try not to blink or move"). For NF visits, show them the visualisation briefly.
  5. Click Start Full Protocol when ready. The pipeline runs automatically from this point.

Visit 1 — Full Protocol

Visit 1 performs the complete baseline recording and feature analysis. No prior data exists; everything is computed from scratch.

What happens automatically

  1. Intake — subject_info.json created; audiometry loaded, PTA computed.
  2. Baseline recording — default 80 s resting-state EEG recorded. Participant screen shows fixation cross.
  3. Full analysis — power, connectivity, and source features extracted; SNR, ICC, and dynamic range computed for each; all features ranked by composite score; top-3 selected; NF target (feature 1) and direction (up/down) stored in analysis_report_v1.json.
  4. Participant screen — switches to NF-ready instruction screen.
  5. NF session — rspv visual launched; 4×(rest+NF) block structure runs; reward signal sent via OSC.
  6. Session complete — all output files written; participant screen shows end screen.
After visit 1 analysis completes, the log panel shows the selected NF target (e.g. alpha_Cz | direction: down | score: 2.87). Check that the selected feature is clinically plausible for this participant before the NF session starts. If it looks wrong, click Abort, investigate the analysis report, and restart NF Session Only with a different protocol if needed.

Visits 2–4 — Quick SNR Check

For visits 2–4 the system reuses the visit-1 NF target unless the SNR or z-score has degraded below acceptable thresholds. The baseline is shortened to 3 minutes (180 s).

What happens automatically

  1. Intake — subject_info.json updated with new visit entry.
  2. Quick baseline — 3 min resting EEG recorded (hard-coded; GUI baseline duration field is ignored for these visits).
  3. Quick SNR check — SNR, ICC, and dynamic range recomputed for the current primary feature only. Sensor-band power features supported; connectivity/source fall back to stored visit-1 metrics.
  4. Decision — if SNR < 1.5 or z < 1.0, the system automatically tries the next backup feature. Decision and reason logged.
  5. NF session — proceeds with confirmed feature.

Visit 5 — Mid-Protocol Evaluation

Visit 5 is a full feature re-ranking mid-protocol. The baseline is 5 minutes (300 s). A 4-rule decision tree then decides whether to maintain or switch the NF target.

Decision tree (runs automatically)

  1. Rule 1 — Primary still in top 3: current feature ranks top-3 in new analysis → maintain.
  2. Rule 2 — SNR degraded >50%: SNR dropped by half or more → switch to new top-1.
  3. Rule 3 — Same modality: new top-1 is same modality (both alpha-band, both connectivity, etc.) → maintain to avoid modality change mid-study.
  4. Rule 4 — Different modality, large improvement: new feature scores ≥30% better → switch. Otherwise maintain.

Read the decision in the log before the NF session starts. It will say something like "Maintain primary: rule 1 — primary still top-3" or "Switch to delta_FCz: rule 4 — 35% better score". If the switch looks clinically wrong, click Abort and discuss.

Visits 6+ — Locked

After visit 5 the NF target is locked. No analysis or re-ranking is performed. The system loads the stored target from the most recent analysis report and runs the NF session directly.

What happens

  1. Intake — subject_info.json updated.
  2. Quick baseline — 3 min (same as visits 2–4).
  3. Locked target loaded — no decision logic. Feature and direction read from stored report.
  4. NF session.

Button Reference

ButtonWhat it doesWhen to use
Start Full Protocol Runs the complete pipeline: intake → baseline → analysis → NF session. Launches participant screen automatically. Normal session start. Use this for all visits.
Baseline Only Records a resting-state baseline and saves the EEG file. Does not analyse or run NF. If analysis or NF needs to be run later / separately.
Analyse Only Runs full feature extraction and ranking on existing baseline data. Does not record EEG. Re-run analysis after adjusting preprocessing parameters, or when baseline was recorded in a previous step.
NF Session Only Loads stored analysis report and runs the NF session. Launches rspv. Does not re-record baseline. If baseline and analysis are already done and only NF needs to run (e.g., after a break).
Participant Screen Manually launches the participant-facing full-screen display. Starts in "waiting" state. If you want to open the participant screen before starting the protocol, or to relaunch it after an accidental close.
Abort red Stops the current operation immediately. rspv is terminated. Participant screen returns to waiting state. Output files up to the abort point are preserved. Emergency stop, or if something looks wrong after analysis results appear.

Participant Screen

The participant screen (antares_gui.py) is a separate full-screen py5 window intended for the second monitor. It reads a shared state file (/tmp/antares_session_state.json) and updates automatically.

StateWhat participant seesWhen
waiting ANTARES logo, "Please sit comfortably and relax" text, three animated breathing dots. Before session starts, after abort, after session ends (if screen stays open).
baseline Fixation cross at screen centre, slowly pulsing concentric ring. During baseline EEG recording.
nf_ready NF instructions: "Focus on the animation. Let it guide you." (localised). Between analysis completion and NF session start.
rest Concentric rings animation, block progress dots at the bottom. During rest phases between NF blocks.
nf Blank dark screen (rspv visual overlaid), block progress dots. During active NF blocks — rspv runs on top.
end Large checkmark, "Session complete. Thank you." text. After successful session completion.
Tip: The participant screen can be launched independently at any time via the Participant Screen button. It starts in waiting state and transitions automatically as the session progresses. If the window is accidentally closed, click the button again to relaunch it — it will re-sync to the current session phase.

Participant screen keyboard shortcut

The participant screen has no visible controls. The only active key is Esc, which closes the window. This is intentional — the participant cannot interact with or dismiss any screen element.

Output Files

All subject data is saved under <subjects_dir>/sub-<id>/.

sub-abcd/ ├── logs/ │ ├── v1.log per-visit operator log (created at intake) │ └── antares.log global log for audiometry / PTA │ ├── audiometry/ │ └── audio.csv thresholds at 9 frequencies + PTA4 (L, R, mean) │ ├── ses-v1b/ baseline EEG folder, visit 1 │ └── baseline_raw_v1.fif │ ├── ses-v1m/ NF session folder, visit 1 │ ├── session_metadata_v1.json protocol, feature, direction, timings │ ├── nf_signal_log_v1.csv per-window reward signal (elapsed_s, raw, corrected, direction) │ └── block_log_v1.csv wall-clock timestamps for each rest/NF block │ ├── models/ │ └── analysis_report_v1.json full feature ranking and selected NF target │ └── subject_info.json demographics + visit history (updated each visit)

Key files explained

FileWhat it containsCreated when
subject_info.json Subject ID, age, sex, creation date, and a visits dict with per-visit metadata. Grows across sessions. Visit 1 intake (subsequent visits update it).
audio.csv Air-conduction thresholds at 125–12,000 Hz for both ears, PTA4 per ear, PTA4 mean. Each visit (audiometry re-processed).
analysis_report_v1.json Feature rankings, scores (SNR, ICC, dynamic range, composite), selected primary and backup features, training direction, site/age/sex used. After full analysis (visit 1 and visit 5).
session_metadata_v{N}.json Snapshot of the exact protocol parameters used for this NF session: feature, direction, protocol type, z-threshold, warmup, block design, timestamps. At the start of every NF session.
nf_signal_log_v{N}.csv Time series of the reward signal. One row per OSC window (~2 s). Columns: elapsed_s, raw_value, rolling_min, rolling_max, direction_corrected, direction. During NF session (appended continuously).
block_log_v{N}.csv Exact wall-clock start and end times for each rest and NF block. Useful for epoch alignment in offline analysis. After NF session completes.
Post-session check: After every session, verify that session_metadata_v{N}.json, nf_signal_log_v{N}.csv, and block_log_v{N}.csv are all present in ses-v{N}m/. If nf_signal_log is missing, the rspv OSC sender failed to initialise — check the log panel for the error.

Troubleshooting

ProblemLikely causeFix
Validation error: "Subject ID must be exactly 4 letters" Subject ID contains digits, spaces, or is the wrong length. Use only 4 alphabetic characters (e.g. jdoe).
"Log file for visit N already exists" This visit has already been run — the duplicate run guard prevents overwriting data. Increment the visit number, or manually delete the log file if it was a test run.
No LSL stream found / recording timeout EEG amplifier not on, or stream name mismatch. Verify the amplifier is running. Use Mock LSL toggle and a recorded file if hardware is unavailable.
"No audiometry directory found" in log Audiometry files for this subject are missing or in the wrong path. PTA will be NaN — session continues normally. Add files later and re-run Baseline Only to update the CSV.
Participant screen does not appear on second monitor The display arrangement may have changed, or the GUI failed to launch. Click Participant Screen again. Drag the window to the correct display manually. Check log for any Python errors from the subprocess.
rspv visual does not open rspv/src/main.py not found, or rspv venv missing dependencies. Check log for "rspv not found" or subprocess errors. Activate rspv venv and re-install dependencies.
Visual shows no reaction to EEG (static) OSC signal not arriving, or max_range_viz == min_range_viz at session start. The first ~40 s (warmup windows) the reward is near 0.5 while statistics build up — this is normal. If still static after 1 min, check the log for "OSC sender" errors. Verify host/port match.
Analysis takes very long or crashes Source-level features require a pre-computed forward model in models_dir. Check the log for file-not-found errors under models_dir. Source features will be skipped if files are absent — analysis continues with sensor-level features only.
"Error: analysis_report_v1.json not found" on visit 2+ Visit 1 analysis was never saved, or the models dir path is wrong. Re-run Analyse Only for visit 1, or correct the models dir path.
Session aborted mid-NF block Operator clicked Abort, or an exception occurred. All data up to abort point is saved. To resume, increment the visit number and run NF Session Only. Do not use the same visit number again.

The operator GUI is a standard desktop window — no special keyboard shortcuts are defined. Use the mouse to interact with all controls.
