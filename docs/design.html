ANTARES

Advancing Neurofeedback in Tinnitus — Code Design & Methodology Reference

Python 3.11 MNE-Python ANT (ant-nf) pcntoolkit py5 / Processing OSC / rspv

System Overview

ANTARES is a closed-loop personalised EEG neurofeedback system for tinnitus research. It records a resting-state baseline, extracts EEG features, scores them against a normative model, selects the most deviant and reliable feature as the training target, then runs a block-structured NF session with real-time visual feedback. The system adapts the training target across visits using a multi-session decision strategy.

Key Design Principles

  • Fully personalised: target selected per-subject, not fixed
  • Normative z-scores drive selection, not raw power
  • Direction-corrected reward: high reward always = moving toward norm
  • Adaptive across visits: SNR checks, mid-protocol re-ranking
  • All outputs are BIDS-compatible or CSV/JSON for reproducibility

Technology Stack

  • ANT (ant-nf) — EEG acquisition, baseline & NF recording
  • MNE-Python — EEG preprocessing, source imaging
  • AutoReject — Automated epoch rejection
  • pcntoolkit — Normative modelling (Bayesian GPR)
  • rspv — Real-time visual feedback (py5/Processing)
  • OSC (python-osc) — Inter-process signal bridge
  • customtkinter — Operator GUI

Pipeline Stage 1 — Subject Intake

Module: pipeline/intake.py

Two functions run at the start of every visit:

get_user_info()

Validates subject ID (4 letters), creates a per-visit log file as a duplicate-run guard, and maintains subject_info.json — a structured record that accumulates demographics and visit timestamps across all visits. This is the authoritative source of subject metadata for analysis scripts.

compute_pta()

Loads audiometry .mat files (one per ear) from audiometry_dir/{subject_id}/. Extracts thresholds at 500, 1000, 2000, 4000 Hz and computes PTA4 for each ear and the binaural mean. Saves to audiometry/audio.csv. PTA4 is a required covariate for the normative model — sessions without audiometry are blocked with an explicit warning.

Pipeline Stage 2 — Baseline Recording

Module: pipeline/baseline.py | Class: ANT.NFRealtime

ANT's NFRealtime is initialised with BIDS session label v{N}b and records resting-state EEG. The baseline duration depends on the visit:

Visit 1
Full duration from config (default 80 s) — used for comprehensive feature extraction and normative scoring.
Visits 2–4
Quick baseline: 180 s (3 min). Sufficient for SNR estimation without full pipeline re-run.
Visit 5
Mid-protocol evaluation: 300 s (5 min). Used for full re-ranking and the decision tree.
Visits > 5
Quick baseline: 180 s. Feature is locked; recorded for longitudinal tracking only.

Pipeline Stage 3 — EEG Analysis

Module: pipeline/analysis.py → preprocess_baseline(), extract_features()

Preprocessing

  1. Load raw .fif from BIDS path
  2. Bandpass filter: 0.1–40 Hz (MNE FIR)
  3. Average reference with projection
  4. Apply EasyCap-M1 montage
  5. Epoch into 4-second fixed-length segments (~20 epochs from 80 s)
  6. AutoReject: cross-validated epoch cleaning (cv=5, interpolation=[1,4,8] channels)
Why 4-second epochs? The original 10 s epochs left only 8 epochs for AutoReject's 5-fold CV, causing underfitting of the rejection threshold. At 4 s, ~20 clean epochs remain after rejection — sufficient for both ICC split-half reliability and spectral estimation.

Feature Extraction

Four feature spaces are computed for all 10 frequency bands (delta, theta, alpha-0/1/2, beta-0/1/2/3, gamma):

Feature TypeMethodDimensionality
Sensor band powerWelch PSD (MNE), trapezoid integration per bandN_channels × N_bands
Source band powerdSPM inverse, mean-flip per aparc label, multitaper PSDN_regions × N_bands
Sensor connectivityCWT-Morlet coherence (mne-connectivity), 1 Hz resolutionN_pairs × N_bands
Source connectivityCWT-Morlet coherence on label time coursesN_pairs × N_bands
Connectivity note: Full all-pairs source connectivity is computationally expensive. For clinical use, consider restricting to a predefined set of clinically motivated region pairs via a regions_of_interest config option.

For each feature, four metrics are computed across epochs (compute_reliability_metrics()):

Pipeline Stage 4 — Normative Scoring

Module: pipeline/analysis.py → compute_dev_scores()

Each feature is scored against a pre-trained Bayesian Gaussian Process normative model (pcntoolkit). The model was trained on a normative population with covariates: age, sex (binary), PTA4, and site (batch-effect correction).

The output is a z-score per feature representing how many standard deviations the subject's feature deviates from the age/hearing-matched norm. Positive z = elevated above norm; negative z = suppressed below norm.

Sign convention: The z-score sign is preserved. The training direction is derived from it: if z > 0, we train down (reduce elevated power); if z < 0, we train up (restore suppressed power). Feature ranking uses |z| so that both directions are evaluated equally.

Pipeline Stage 5 — Feature Ranking & Selection

Module: pipeline/analysis.py → rank_features()

All features are ranked by a weighted composite score:

composite_score = 0.30 × min(|z| / 3.0, 1.0)       # normative deviance (30%)
               + 0.25 × min(max(ICC, 0), 1.0)        # reliability (25%)
               + 0.20 × min(SNR / 10.0, 1.0)         # signal quality (20%)
               + 0.15 × min(DR / 2.0, 1.0)            # dynamic range (15%)
               + 0.10 × min(stationarity, 1.0)        # temporal stability (10%)

A feature meets criteria if: |z| ≥ 1.5, ICC ≥ 0.6, SNR ≥ 2.0, DR ≥ 0.3. The top viable feature is selected as primary; the next three as backups. If no feature meets criteria, the best-scored feature is selected with a relaxed_criteria flag.

Adaptive Multi-Session Logic

Module: pipeline/session_manager.py → SessionManager

Visit 1
Full baseline (config duration) → full analysis → select primary + 3 backups. Baselines for the normative z-scores.
Visits 2–4
Quick baseline (3 min). Re-compute SNR for the primary feature only. If SNR < 1.5 or |z| < 1.0, switch to backup #1, then #2. If all fail, keep primary with a quality warning.
Visit 5
Mid-protocol evaluation (5 min). Full re-ranking. Apply the 4-rule decision tree (see below).
Visits > 5
Feature is locked. Quick baseline is recorded but no switching occurs. The selection report from the previous visit is carried forward.

Session 5 Decision Tree

Applied when the full re-ranking is complete at session 5. Rules are evaluated in order; the first match wins:

if prev_primary in new_top_3:
    → MAINTAIN  (still ranked highly, no reason to switch)

elif new_SNR < prev_SNR × 0.5:
    → SWITCH to new #1  (primary SNR dropped >50% — signal quality degraded)

elif new_modality == prev_modality:
    → MAINTAIN  (within-modality drift is acceptable; avoid unnecessary change)

elif new_score ≥ prev_score × 1.30:
    → SWITCH to new #1  (different modality, ≥30% better score — worthwhile switch)

else:
    → MAINTAIN  (different modality but not convincingly better)

The decision and reasoning are stored in session_decision within the selection report JSON for audit purposes.

OSC Signal Flow

1
ANT computes EEG feature

1 Hz windows. Feature value is raw band power (µV²/Hz) or coherence [0–1]. ANT applies internal smoothing: signal_smoothing=0.25, display_smoothing=0.3.

2
RspvOSCSender._forward() — pipeline/session.py

Maintains a rolling min/max over the last 60 windows. Applies direction correction: for "up" training, inverts the value (corrected = min + (max − value)) so that higher feature always maps to higher reward. Logs to CSV. Sends /rspv [min, max, corrected] via UDP to localhost:5005.

3
SignalHandler.osc_handler() — rspv/src/signal_processing/signal_handler.py

Normalises: (corrected − min) / (max − min) → clamp [0,1] → scale to [min_range_viz, max_range_viz] = [0.0, 1.0]. Stores as latest value under a threading lock (no competing background thread).

4
VisualBase.get_smooth_signal(alpha=0.08) — rspv/src/visuals/visual_base.py

Single-point exponential smoothing, called once per draw frame (30 fps). Time constant ≈ 0.36 s. Consistent across all visual presets.

5
Visual drives rendering

Reward score ∈ [0, 1]. Each visual maps it to its visual parameter: VisualTree maps to leaf count (0→min_leaves, 1→max_leaves). 1.0 always means maximum reward, regardless of training direction.

Reward Direction Logic

The training direction is computed from the normative z-score sign:

direction = "down"  if  z > 0   # feature elevated → suppress it
direction = "up"    if  z < 0   # feature suppressed → restore it

Before this correction, all visuals assumed "low feature = more reward" — which was correct for "down" but backwards for "up". The fix is applied at the OSC sender level so that rspv always receives a direction-corrected reward score. No changes are needed in individual visuals.
